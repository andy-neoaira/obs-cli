# Vault 安全路径策略

- 对应共同规范：`vault-contract/v1` 的 VC-1、VC-2.2、VC-2.3
- 实现包：`pkg/pathpolicy`
- 稳定越界错误：`PATH_OUTSIDE_VAULT`

## 解析流程

所有普通内容操作都必须把 Vault 逻辑路径交给同一个 resolver：

1. 将 Vault 根目录转成绝对路径并解析根目录自身的符号链接。
2. 拒绝空路径、绝对路径、`~`、盘符、UNC、NUL、ADS、空路径段、`.` 和 `..`。
3. 将人类输入中的平台分隔符转为协议使用的 `/`，但不改变 Unicode 或大小写。
4. 已存在目标解析全部符号链接，再验证真实目标仍位于真实 Vault 根目录。
5. 新目标向上找到最近存在的父目录，解析该父目录后再验证 Vault 边界。
6. 返回规范的逻辑路径、文件系统目标和目标是否存在。

边界判断使用 `filepath.Rel` 的路径段语义，不使用字符串前缀。

## 隐藏路径

普通 Note、附件、模板、Daily Note、扫描、搜索与批量修改默认拒绝任意以 `.` 开头的路径段，包括：

- `.obsidian/`
- `.git/`、`.hg/`、`.svn/`
- `.trash/`、`.Trash/`
- `.obs-cli/`
- 其他用户隐藏目录

`.obsidian/*.json` 只能通过专用只读配置接口访问。未来若增加隐藏路径写能力，必须使用显式、可审计的 capability，不能改变普通 resolver 的默认策略。

## 接入边界

- `obsidian.ValidatePath` 是旧业务代码的兼容入口，内部只委托给 `pkg/pathpolicy`。
- Create、Delete、Move、Daily、模板读取、Note 读写和链接重写均在文件操作前完成路径解析。
- Move/Delete 在解析前补齐 `.md`，避免“校验一个路径、实际修改另一个路径”。
- Vault 内符号链接可以安全读取；普通写入若经过符号链接则返回物理身份冲突，要求改用无歧义的规范逻辑路径。
- 扫描到 Markdown 符号链接时仍再次解析；指向 Vault 外部的链接令整个读取或批量修改失败。

路径解析、revision 前置条件与统一原子存储层共同缩小检查和文件操作之间的竞态窗口；
当前所有 CLI 内容写入口都必须通过相同路径门禁，不能借逻辑路径或已有符号链接逃逸。
